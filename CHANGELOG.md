# Changelog

Beacon's releases, newest first. Installers for each published version are on the
[Releases](https://github.com/OAraLabs/beacon/releases) page, which is also the update feed: Beacon 0.3.0 and
later update themselves.

## Unreleased

- **Integrations → Home: what Prometheus can touch.** A new Home row under Integrations (owner devices only) shows one line for the connection ("Connected to Home Assistant · 13 devices", or what is wrong, in words), every device grouped by room with its state and its tier as a word and a shape, a search box and a tier filter. Critical devices show a lock and "Read only"; a device Prometheus has not classified is shown Sensitive, with a note. A Sensitive device can be set to "Ask once" (behind a confirmation that names it), which means its next approval offers Always allow; it grants nothing by itself. The Always allowed list sits at the top, with Revoke on every row. Each device has "Open in Home Assistant"; there is no on/off control here. The Home row appears only on a Prometheus that says it supports Home, so nobody is shown a Home page that opens on an error. Built against made-up fixtures (`docs/HA-UI-DATA-CONTRACT.md`).
- **Critical approvals: steadier about what Prometheus supports.** Beacon takes a Prometheus's silence to mean "it doesn't mark approval requests critical" only while its live socket is connected, and only if it has never said; time spent reconnecting no longer counts, and silence never withdraws a yes. A view that was never told the rule now offers no short Approve. And an approval card stops showing its key hints when the button that had focus goes away.
- **Approvals: no stray keystroke, and critical requests only from the card.** The `A` and `D` keys used to answer the first approval card from anywhere in the window that wasn't a text field, so a letter typed at a list or a button could approve a command nobody had read. They now answer only the card focus is on (click a card, or Tab to one of its buttons), a held key does nothing, and each card says so and shows its key hints only then. And a request a newer Prometheus marks critical can be approved only with the button on its full card: `A` does not approve it, its row on Mission and Today offers "Answer on the card" in place of Approve once, and so does its line in the desktop-prompt pane. Deny is unchanged everywhere. With a Prometheus that does not mark requests, only the focus rule for the keys changes; for the first seconds of a connection, before Prometheus has said what it supports, a request is treated as critical.
- **Critical approvals are answered in Beacon.** A newer Prometheus marks some approval requests critical: ones that can't be judged from a notification's one line, or are too consequential to approve with one tap. For those, Beacon's notification now has no Approve or Deny button and says to answer it in Beacon; clicking it opens the window, where the whole request is shown. Prometheus decides which requests these are, and Beacon never guesses. With a Prometheus that doesn't mark requests, notifications are unchanged.
- **Home Assistant approvals get their own card.** When Prometheus says an approval is for a Home Assistant control, the card names the device and room, shows its tier as a word and a shape (Ordinary, Sensitive or Critical, never colour alone) and what would change ("Hall light: off → on, 60%", or "current state unknown"). "Always allow…" is offered only for an Ordinary device, or a Sensitive one with "Ask once" on, and only when Prometheus offers it. A Critical device can only be denied, with a sentence saying why. A call on many devices lists them all, collapsed past 5 with "and N more". After you approve, the card shows what Home Assistant really reports: ✓ Confirmed, or ⚠ Not confirmed when it accepted the command but the device still reads otherwise. Needs a Prometheus that sends the new `home` details; any other approval looks as before. Built against made-up fixtures (`docs/HA-UI-DATA-CONTRACT.md`).
- **Home Assistant approvals get their own card.** When Prometheus says an approval is for a Home Assistant control, the card names the device and room, shows its tier as a word and a shape (Ordinary, Sensitive or Critical, never colour alone) and what would change ("Hall light: off → on, 60%", or "current state unknown"). "Always allow…" is offered only for an Ordinary device, or a Sensitive one with "Ask once" on, and only when Prometheus offers it. A Critical device can only be denied, with a sentence saying why. A call on many devices lists them all, collapsed past 5 with "and N more". After you approve, the card shows what Home Assistant really reports: ✓ Confirmed, or ⚠ Not confirmed when it accepted the command but the device still reads otherwise. The Home card shows only when the Prometheus you are on says it supports Home; any other approval looks as before. A Home approval is never answered from a notification (it says to answer in Beacon), and one answered somewhere else, such as a chat app, becomes "Answered on …" with no buttons. A link to Home Assistant opens only if it is https, or plain http to a private or tailnet address, and never if it carries a name, password or token. Built against made-up fixtures (`docs/HA-UI-DATA-CONTRACT.md`).
- **Files handed to Beacon, and refused links: three follow-ups.** When Beacon refuses a `beacon://` link, its notification now says only that a link was blocked; it used to show the first 80 characters of the link, so whoever made the link could put words of their own in a Beacon notification. A file handed over with Open With (or dropped on Beacon's icon) is now looked at, and read, by a small helper process: a file on a disk that has stopped answering, such as a network share whose server went away, used to be able to freeze every Beacon window, and now costs a wait of a few seconds and a line saying Beacon could not look at it, while the other files handed over with it are still offered. And files handed over from a system folder (`/etc`, `/var`, `/Library` and the like), from anyone's Library on any disk, or from a Linux snap app's data folder are refused like hidden files already were, with a note that the paperclip still attaches them: those places have no dot in their path, so the hidden-file rule missed them.
- **Work in a folder.** A conversation's header now always shows the folder your assistant is working in, or No folder; if Beacon can't check just now, the chip stays and says so. When Prometheus shares this computer's disk, the chip's Choose a folder… opens the system's folder picker. Beacon then lists, in plain words, what your assistant will do in that folder in this conversation (change and delete files without asking each time, run commands, follow instruction files it finds there, keep a copy each turn for undo), and sets it only on Use this folder. Stop using this folder takes it back and leaves the files alone. A folder is judged by where it really is, so a link that leads to your whole home folder, a whole disk, a system folder, or the folders that hold keys and settings is refused. Beacon proves the shared disk before offering the picker (Prometheus has to see a folder Beacon just made), so a Prometheus reached through a tunnel or a container isn't mistaken for one on this computer; there, and on another computer, the chip still shows the folder and explains how to set one. An approved device doesn't get the chip.
- **Open files with Beacon.** On a Mac, Beacon is now in Finder's Open With list for common documents and pictures (never as the app they open in by default), and a file can be dropped on Beacon's icon; on Linux, a file's path can be given on the command line. Beacon then shows a confirmation with each file's name, kind and folder, and reads none of them until you answer. Adding takes a click with the mouse or trackpad: the keyboard can only say Don't add, and the add buttons wait a moment after the screen appears or Beacon comes to the front, so a key or click meant for something else adds nothing. Add to a new conversation, or to the open one, puts the files in that message box as attachments; nothing is sent until you send it. Not added, each with its reason: links to other files, hidden files and anything in a hidden folder, Beacon's own files, files in your Library (other than a cloud drive's folders) or inside an application, folders, empty files, and files over 20 MB. A file that changes between being shown and being added is left out, and Beacon says which. Files handed over while a confirmation is up get their own confirmation after it.
- **Links say where to go and nothing else.** A `beacon://open` link that carries anything besides which conversation to open (text, a prompt, any other parameter) is now refused whole, where it used to open the conversation and ignore the rest. A link opens only a conversation this Beacon already has. No link can put words in a message box or send anything.
- **Add a tool server at an address.** Config → Connectors → Add server now takes a server at an https:// address (Streamable HTTP or the older SSE), with the token it signs in with, as well as a command that runs on the Prometheus computer. The token goes to Prometheus, which keeps it; Beacon does not keep it, cannot show it again, and blanks it from any refusal that quotes it. A server's card says it signs in with a token Prometheus keeps, by header name only. An http:// address is accepted only where Prometheus reaches it privately: on its own computer, its home network or Tailscale. A key in the address itself is refused, since an address is kept and shown as it is. If Prometheus is still connecting to the server when Beacon stops waiting, Beacon says so and shows the list, where it used to report a failure. A Beacon that signs in with a device key is told plainly that adding or changing servers needs Prometheus's main key (Settings → Connection → Advanced), and is no longer offered buttons that Prometheus would refuse.
- **Quick capture takes files and screenshots.** The ⌘⇧Space box now carries more than text: ⌘V adds a copied file or image, the paperclip picks files, and the camera takes a screenshot of a screen or a window, with the box itself stepping out of the picture. Each shows as a chip you can remove before sending, and a file over 20 MB is refused with its size. Send to lists New conversation first, then your recent conversations by title (it used to list ids). If a send doesn't go out, the text and the files that didn't go are put back in the box, along with anything you typed meanwhile, and the box says how far it got. Esc waits for a send to finish before closing the box. Quick Capture is also in the app menu, for when another app holds the shortcut. Dragging a file in from another app isn't offered: clicking that app closes the box.
- **Everyday mode, and a Today home.** A new install opens on the everyday views: Today, Chats, Workspace (Documents, Artifacts, Wiki, Files) and Config with the settings you change. Today answers three things: what needs you (an approval, a message with no reply, messages that could not be sent), what happened since you last looked (replies by conversation, tasks that finished or failed), and what is coming up. Settings → Views → Show everything brings back Mission, Coding, Activity, the Board and the rest, and the command palette has the same switch. An install that already exists keeps everything, and nothing changes for it until that switch is turned off. The mode changes only what is shown.
- **Starters and saved prompts.** The new-chat screen has a row of starters under the message box: Plan my day, Summarise this, Draft a reply and Research a topic to begin with, and any prompt you save. Clicking one puts its text in the message box; nothing is sent until you send it. Save as a prompt… keeps what you have typed under a name, and Edit prompts… changes or removes them (the built-in ones too, and you can bring those back). A saved prompt is also in the command palette (Use prompt: …) and in a conversation's message box: type `/` and its name. A prompt whose name is already a `/` command, or has no plain letters or digits, is kept without a `/` name. Holding Enter no longer sends a message: only the first press does. Prompts are kept on this computer, the same whichever Prometheus you are on.
- **Tests: probes can copy a profile that keeps two Prometheus while Beacon is open.** The copy now reads each database the way that file needs, where it used to fail on the Prometheus Beacon wasn't on.
- **Approving a phone says what it grants.** The "Approve new device?" prompt's button is now Approve as chat-only, which is what an approval gives. Make it an owner… shows how owner powers are granted (only from the computer Prometheus runs on): the steps, and the exact command, `oara pair --owner`, with a Copy button. Config → Devices lists the devices waiting to join, with Review to bring the prompt back after Not now. When a device asks while Beacon isn't in front, a notification says so, without the requester's own device name.
- **Devices errors in plain words.** Config → Devices no longer shows raw daemon errors like "HTTP 401: minting a device token requires the global token": each says what to do (for a phone, use Add a phone).
- **Add a phone.** The title bar's switcher and Config → Devices offer Add a phone…: a QR the phone scans to ask that Prometheus to let it join, which you then approve in Beacon. There's no password in it, only the name the phone reaches the Prometheus by and the computer key Beacon checked for it, so the phone can check it too before sending anything. It always uses a name the iPhone app accepts (a short Tailscale name, never a number address like 100.x or localhost), and when it can't make one it says what to do: turn on Tailscale, connect by name, turn on Other computers, or update an older Prometheus.
- **One line per Prometheus in the sidebar.** Each row under Your Prometheus is now its dot, its name and a short muted detail (the model it's on, or its state in words when it isn't connected), cut short with an ellipsis; the full line is in the tooltip. An older Prometheus's "can't prove who it is" is a small warning icon at the end of its row, with the sentence as its tooltip, and Add a Prometheus is the + in the Your Prometheus header, like the one beside Sessions.
- **Add a Prometheus from the title bar.** Click the name in Beacon's title bar ("Beacon" while you have one Prometheus) and choose Add a Prometheus…: a short form takes its address, socket and key, Test asks who answers there without sending any key and tries the key on it alone, and Add keeps it beside the others and switches to it. The Prometheus you're on is never touched: not its saved address, not its key. An address Beacon already keeps says so, and nothing is added. Settings → Connection → Advanced now edits only the Prometheus you're on; a new address there that turns out to be another Prometheus offers Add a Prometheus… instead of adding it.
- **A dialog over a view's header can be clicked.** The top of a window drags it, and that included Mission Control's header and an open conversation's header, even under an open dialog: the ✕ and "Advanced" in Connection Settings, drawn over them, moved the window instead of answering the click. While any dialog, menu or popover is open, nothing under it drags the window now, in every view; the title bar drags it again once it closes.
- **Connection Settings keeps the keyboard.** Tab and Shift-Tab move only through the dialog's own controls, Esc closes it, and focus goes back where it was.
- **When Settings opens, Beacon notes what changed the view.** One line in `logs/view-trail.log` in Beacon's profile folder: the view on screen, the last few changes of view and the click or shortcut before each, and how long the window has been loaded. Typing is never recorded. It is there to explain a view that jumps when Settings opens.
- **The pairing code includes the Prometheus node key for the phone to pin.** The code in Devices → Enrol now ends with `node=`, the computer key Beacon pinned for that Prometheus when it proved who it is. A Prometheus too old to have a computer key gets the code as before, without it.
- **A Prometheus with no vault adopted yet is still the same Prometheus.** A Prometheus says no instance id on a boot where it hasn't adopted its vault yet. Beacon took that, from a Prometheus whose computer key it knows, for a different Prometheus answering, and sent it nothing. Now the computer key is what proves it: no instance id this boot says nothing against it, and the first instance id it says is remembered. Another instance id under the same key is still a different Prometheus.
- **Tests: probe:onboarding-welcome follows the live first run.** Its first scenario still expected the old setup wizard on an empty profile; since the new first run went live it checks that Welcome opens with no flag. All 51 checks pass.
- **Switch from any view.** With two or more Prometheus, the name in Beacon's title bar is a button: click it, or Tab to it and press Enter, and the same list as the Chats sidebar opens, from Mission Control or anywhere else. The arrow keys, Home and End move, Enter switches, and Escape closes it. With one Prometheus the title bar still just says Beacon.
- **The Prometheus you keep, in the sidebar.** With two or more, "Your Prometheus" at the top of the Chats sidebar has a row for each: its name, how it is doing in words beside a coloured dot (Connected, Connecting…, Can't reach it since 3:12 pm, No longer accepts this Beacon, A different Prometheus answered, No longer proves who it is, Not encrypted), which AI it's on, and a note on an older Prometheus that can't prove who it is. Click a row to switch; Beacon stays in Chats, and pop-out conversations close first, each keeping its draft with its own Prometheus. A Prometheus that fails the identity check is never sent a key: switching to it shows its card. The name of the one you're on is in the title bar, the window title, the composer ("Message Home mini…") and the can't-reach banner. "Add a Prometheus…" opens Settings → Connection for now. With one Prometheus nothing changes.
- **A Prometheus with no computer key yet connects, and one that had a key and lost it doesn't.** A Prometheus 0.9.18 that hasn't made its computer key yet answers Beacon's "who are you?" with "no key yet". Beacon used to take that for no answer and retry forever, so it never connected. Now one Beacon never knew a key for connects as an older Prometheus does, and one that proved who it is before is refused, with nothing sent, saying it no longer proves who it is.
- **Tests: smoke:discovery-confirm no longer races the clock.** Its check that a computer found just before the search window closes is still listed depended on real timing and could fail on a slow machine. The test now closes the window itself, at the moment it is checking.
- **Setup's download size comes from the release itself.** Before getting Prometheus, the confirmation now says the size the current release gives, read when the screen opens (only the release's small description file, never Prometheus itself). If it can't be read within a few seconds, the screen keeps the size built into Beacon, and it never waits to show it.
- **Setup says the right download size.** Before getting Prometheus, the confirmation said about 71 MB, the size of an older Prometheus. It now says about 72 MB, the size of Prometheus 0.9.17, which is what it downloads.
- **A part-way setup with a pairing Prometheus no longer accepts goes back to pairing.** If Prometheus on this Mac was set up again after Beacon paired with it, Beacon used to resume setup at "How should your assistant think?" with a pairing that couldn't work. It now checks the saved pairing first and, if it's refused, opens Connect saying to pair again.
- **Try again connects once.** Pressing Try again while Beacon was still retrying an unanswered Prometheus could connect twice, dropping the first connection.
- **A new address that leads to another Prometheus is no longer taken for the same one.** Settings → Connection asks who answers at a new address before saving, without sending a key. If it's a different Prometheus, nothing is saved and you're offered to add it as a new one (with only a key you type for it); if it's one Beacon already keeps, you're offered to switch to it. Editing an address no longer leaves a second copy of the same Prometheus in the list.
- **Beacon checks on the other Prometheus it keeps.** Every 60 seconds (every 5 minutes for one it can't reach), each Prometheus Beacon keeps but isn't on is asked how it is and which AI it's on, with its own key and only after it has proved who it is. Nothing is relayed between them. The list that shows this comes in a later release.
- **Beacon keeps each Prometheus it has connected to.** Each saved connection (its name, address and pin) and the facts about its key now live with that Prometheus, so connecting to another one no longer overwrites the first, and Beacon can switch between them (the list to switch from comes in a later release). Set up again forgets only the Prometheus you are on. On the first launch Beacon moves the saved connection into its Prometheus's folder.
- **Spec: Beacon is a client, never a router.** [docs/MULTI-PROMETHEUS.md](docs/MULTI-PROMETHEUS.md) §2 rule 5: Beacon shows and controls each Prometheus, but never relays tasks, messages or approvals between them; work between instances goes Prometheus to Prometheus.
- **No key before proof.** Before Beacon sends a Prometheus its key, on every connect and every redial, the Prometheus signs a fresh nonce with its node key, and Beacon checks it against the key it pinned for that Prometheus. Another key gets nothing, and a card like SSH's host-key warning says so; the same Prometheus with a new key (moved to new hardware) waits for you to confirm. A Prometheus too old to be asked connects as before until it can prove who it is; one that could prove it and stops is refused.
- **A key only goes to the Prometheus that gave it.** Beacon keeps each Prometheus's key in that Prometheus's own folder, so pointing Beacon at another Prometheus no longer hands it the old one's key. The settings that talk to the connected Prometheus read its address and key together. Beacon no longer follows a redirect to another address (a redirect could re-send a message there), and Settings → Test sends the saved key only to the saved address. On the first launch the existing key moves, backed up first, into the folder of the Prometheus it belongs to.
- **Each Prometheus keeps its own conversations.** Pointing Beacon at a different Prometheus (Settings → Connection, or Set up again and join another) used to leave the old one's conversations in the sidebar, send messages queued for the old one to the new one, and let Approve on an old notification answer the new one. Beacon now keeps a folder per Prometheus (conversations, queued messages, drafts, groups), told apart by the Prometheus's own fingerprint, and a notification's buttons only answer the Prometheus that asked while it is still the one connected. On the first launch Beacon backs up its cache, then moves it into the folder of the Prometheus it is connected to. Your theme, window and notification choices stay Beacon's own.
- **Spec: one Beacon, several Prometheus.** [docs/MULTI-PROMETHEUS.md](docs/MULTI-PROMETHEUS.md) says how Beacon will hold more than one Prometheus at once: a folder and a key per Prometheus, a list in the sidebar, one approvals inbox, and the PRs that build it, red tests first.
- **Computer use: start the next desktop task.** After a desktop task ended, the progress pane showed only that task and offered no way to start another in the same conversation. The start form now comes back under an ended task. It still never shows while a task runs.

## 0.4.9 (2026-10-20)

Beacon's source is public, under the [MIT License](LICENSE). This release also carries the work of 0.4.6 to
0.4.8, which were never published.

- **Open source.** The license is MIT, the same as Prometheus. Settings → About and the About box say "Free ·
  open source (MIT) · beta". The disk image no longer asks you to agree to a license before it opens, and
  the AppImage no longer asks on its first run. See [PRIVACY.md](PRIVACY.md) for what Beacon connects to,
  and [TRADEMARKS.md](TRADEMARKS.md) for the names.
- **Plain words for an approved device.** A Beacon that another Beacon approved sees short explanations
  instead of Prometheus's refusals.
- **No plain http to the internet.** Beacon refuses an unencrypted connection to an address that is not this
  computer, your home network or Tailscale, saved connections included, and says to use https or Tailscale.
- **"Make this Beacon an owner"** is offered at the end of joining another computer, and opens only the owner
  section. Settings keeps the address and key under Advanced.
- **Task lists in chat** show their checkboxes, without bullets as well.
- **Zero tool calls** read "No tool calls yet", without a red 0%.
- **Model rows read UP or DOWN** from a fresh check, never "stale" a minute after Prometheus starts, and a
  stopped local server reads DOWN. A cloud default model is named by its model, not "Local".

## 0.4.5 (2026-10-17)

Includes 0.4.4, which was not published on its own.

- **Prometheus on the same Mac:** approve this Beacon with Prometheus's own `oara pair approve`, with no other
  Beacon needed. The download is about 71 MB.
- **Several conversations at once:** side by side in the main window, with a divider you can drag, or popped
  out into their own windows.
- **Projects in the sidebar:** file sessions into projects by drag or right-click, with suggestions from the
  paths your assistant worked in. The sessions list can be resized.
- **Pages, SVGs and PDFs in chat** can be viewed, not only downloaded, and a plain click on a link to a local
  address opens it in the browser pane.
- **"Tidying up the conversation…"** shows inline, with a progress bar, while a long conversation is compacted.
- **Fixes:** a wiki page's YAML frontmatter is no longer shown as page text; refused tasks read "refused" on
  Mission; the dock and panes fit inside the window; on Linux, no spellchecker dictionary is downloaded from
  Google; the voice port is 8012 by default and set in config.

## 0.4.3 (2026-10-12)

- **Pairing codes for iPhone are encrypted when Prometheus is.** With home network on, the code from Config →
  Devices → Enrol carries Prometheus's key, so a Beacon for iPhone connects over TLS, and only to that
  Prometheus. Beacon first checks that Prometheus answers on the iPhone ports (8006 and 8011) with that key,
  and makes no code if it doesn't. Phones paired before home network was turned on need a new code.

## 0.4.2 (2026-10-12)

- **Change which AI your assistant uses, from Beacon:** Config → Models → Main model. Beacon checks a key
  before saving it; "Restart now" restarts Prometheus to apply it (Prometheus 0.9.7 or later).
- **Make a Beacon on another computer an owner** with a one-time code from `oara pair --owner`.
- **More ways in** when Prometheus is already on this Mac: look for another computer, or type its address.
- **Fixes:** the approval card is solid over every page; a worker request this Beacon can't approve says so
  once and explains how to approve it; the address example is generic.

## 0.4.1 (2026-10-11)

- **Setting up Prometheus on a new Mac works:** 0.4.0 asked for the download at the wrong address.
- **A Mac too old for Prometheus** is told so before anything downloads.
- **"We couldn't find Prometheus" says why:** macOS isn't allowing the search, the Prometheus found needs
  updating, or nothing answered (and you can type the address).

## 0.4.0 (2026-10-11)
